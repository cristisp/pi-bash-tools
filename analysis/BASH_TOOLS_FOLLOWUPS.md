## Newly discovered F7 scope

Single-flight is process-local.
The in-flight registry lives in the producer process and is not shared by separate Pi or child-session processes.

Flow publication shares completed evidence through the flow store.
It does not coordinate executions that are already running in another process.

A flow-published call from a separate producer process can therefore report `cacheDecision: "miss"`, execute independently, and return the same content-addressed ref as another call.
`producerScope: "flow"` describes evidence publication scope, not active-execution coordination scope.

`concurrentExecutions` is measured within one producer process.
A value of `1` across separate child processes does not prove that the processes did not overlap.

The producer's deterministic v1.0.2 integration coverage validates overlapping identical read-only calls within one process with one execution, shared metadata, and `concurrentExecutions > 1`.
A durable cross-process single-flight mechanism would be a separate feature requiring an inter-process claim or lease, expiry, ownership, and crash recovery.

## Fresh consumer evidence

The final flow-published probe used four identical calls:

```text
verify({
  omit: ["format"],
  publish: { flowId: "f337ad2fbb0e26406" }
})
```

The four records were valid, flow-published, and returned one ref and one repository-state digest.
Each producer process reported a cache miss and executed independently, producing four executions for one digest.
This confirms the publication boundary and is expected under the process-local F7 contract.

The omitted `format` phase makes the consumer verdict incomplete by design.
The probe was intended to exercise non-mutating cache eligibility, not the full validation gate.

## Digest boundary discovered by F8

`dirtyFilesDigest` is a fingerprint of the paths reported by Git, including their content, mode, size, and status.
Paths excluded by `.gitignore` are not in the fingerprint.

A tracked modified file changed the digest when its content changed, including a same-size edit.
Restoring its original bytes restored the earlier digest.
An edit to ignored `PLAN.md` did not change the digest because that path was not an input.

The consumer must treat a ref as evidence for the recorded repository state, not as a content lock.
A role that edits again must mint new evidence.
